# Local model evaluation

Pinned weights: official Google `gemma-4-E2B-it-qat-q4_0-gguf`, revision and SHA-256 in the shipped model manifest. Inference runtime: llama.cpp b11852, x64 CPU, four threads, no GPU, one slot, 8192-token context, temperature 0.1, thinking disabled, 1800 output token maximum.

The opt-in integration test starts from a synthetic recording of a single careers-page-to-spreadsheet transfer. It invokes the production discovery prompt and actual local model; no expected workflow response is substituted. It then invokes production extraction on two previously unseen source layouts with different company/job values and an absent optional salary, asserting the new values and absence of the demonstrated ones. Reports are produced under `KOPI_REPORT_DIR`.

Earlier trials demonstrated that asking this small model for a broad workflow spec through JSON syntax alone was insufficient: it invented actions and memorised source navigation. A full schema constrained syntax, but not action semantics. Constraining the *available adapter* from observed destination evidence and narrowing the discovery prompt improved the tested case. This constrains execution capabilities, not expected field answers: the model still infers the goal, field names, extraction descriptions, ordering and optionality from the recording. There is no internship-specific extractor or hardcoded model response.

The revised tests passed twice; measured combined discovery and two extractions were about 42 seconds and 30 seconds respectively, with approximately 4.5 GiB resident memory after inference. Model weights on disk are 3.35 GB. OS page cache, transient loading peaks, browser and WPF are not represented by the resident-model measurement. The cloud machine has about 33 GiB RAM and differs from the user's 16 GB integrated-graphics laptop. Do not present these numbers as expected laptop latency or a comprehensive benchmark.

The actual Chrome extension + bridge + generic form path is covered by Windows CI. The Google Sheets adapter additionally has a simulated name-box/clipboard/CSV fixture. Real Sheets, its permission prompts, authenticated export and website timing still require user validation. Two source layouts and one task do not establish broad production reliability. More demonstrations and adversarial tasks would be valuable later; finish the real-account acceptance test before expanding scope.
